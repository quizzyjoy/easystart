# hm_easystart 快速启动（EasyStart 仓 · HarmonyOS 模板线）

> 多端（手机 / 平板 / 2in1 / TV / 手表）HarmonyOS 应用模板 · API 23 基线 · 状态管理 V2 · HDS 组件
> 本仓（EasyStart）是蓝图模板的**权威上游**（多模板线：现行 `hm_easystart/`、预留 `oh_easystart/`）；**工程根 = `hm_easystart/`**（构建/运行的工作目录），仓级文档在 `docs/`；下游 fork 应用对 `quizzyjoy/` 三库只读（指南 §12.3）。
> 完整规范见同目录 `鸿蒙工程目录设计指南.md`（权威宪法）；其可视化版见 `design-guide.html`（设备形态图在 `assets/`）。
> UX 设计契约（设计理念 / 体验标准验收清单 / 高端精致能力索引）见 `UX设计指导.md`。
> 模板待演进事项见 `TODO.md`；提交规范见 `git_constraints.md`；文档总索引见 `README.md`。

## 1. 工程结构（15 模块：3 共享 HAR + 5 应用级 HAR + 3 特性 HAR + 4 入口 HAP）

```

├── AppScope/                  # 应用级配置 + 颜色设计令牌（app_* × 46 + qj_* × 3 = 49）+ 图表色卡 chart_c01~c20（base/dark 双份，v3.0/v3.23）
├── quizzyjoy/                 # ★ 跨 app 共享三库（@quizzyjoy/* 组织级资产；未经授权不可修改，见目录内 README 与指南 §12.3）

│   │                          # / 权限 / 国际化 / 窗口 / 方向 / 屏幕 / 震动 / 分享

│   ├── AppCommon/             # 项目 Common：AppBootstrap 启动装配（仅编排） @easystart/app-common

├── features/
│   ├── HomeFeature/           # MVVM 三分包示范（view/viewmodel/data），fork 后替换为真实 feature
```

**包作用域规范（指南 §12.3）**：共享三库 = 组织作用域 `@quizzyjoy/*`，v3.11 起物理隔离到独立顶层目录 `quizzyjoy/`——它们是**组织级多项目公共库，本仓库只是暂存地**（未来可迁独立仓库供多 app 共用）；**fork 应用只消费、无权修改（不新增/不改/不加导出），改动一律走本模板上游轮次**；应用自有 HAR = 仓库名末段 `@easystart/*`（app-common / home-feature，复制模板到新应用时整体替换为新应用作用域）。

依赖方向严格单向：`product/* → features/* | AppCommon → Platform → Foundation`；VitalUI 仅依赖 Foundation。
**共享库 vs 项目 Common**：Foundation/Platform/VitalUI 回答"换一个 app 还能用吗"（能→共享库）；AppCommon 回答"本 app 特有的决策"（装配链编排）。判据表见指南 §17。
手表入口不依赖 VitalUI / HomeFeature（纯原生压体积），但与另两入口共用 `AppBootstrap` 装配链。

## 2. 构建与运行

> **工作目录 = 工程根 `hm_easystart/`**（`build-profile.json5` 所在处；仓根不是工程根，`docs/` 为仓级文档）。

```bash
# 安装依赖（ohpm 不在 PATH 时用绝对路径）
ohpm install

# 构建（产出 4 个签名 HAP + App 包；多 entry 必须显式指定模块）
devecocli build --modules entry entry_pc entry_tv entry_wearable

# 运行到指定设备
devecocli run --device 127.0.0.1:5555 --module entry
devecocli run --device 127.0.0.1:5561 --module entry_pc
devecocli run --device 127.0.0.1:5557 --module entry_tv
devecocli run --device 127.0.0.1:5559 --module entry_wearable
```

四形态冒烟（v2.1，2026-09-24）：foldable=md@711.68vp、tv=lg@1280vp、wearable=xs@233vp、2in1=lg@1100vp（v2.3.2 起 2in1 由 entry_pc 承载，bp_2in1 模拟器全链验证 + dumpLayout 实证）。
体积（v2.3.3）：entry 893.5 KB / entry_pc 893.2 / entry_tv 822.7 / wearable 387.9（卡片骨架 +59.3 KB/入口，wearable 卡片+备份 +49.2）。
三方依赖版本集中在工程根 `hm_easystart/VersionFile.json5`（oh-package 以 `@param:` 注入，需 `"parameterFile": "VersionFile.json5"` 声明，见指南 §8.2）。

```bash
# release 构建（混淆：4 入口 buildOptionSet.release 均已接线，规则见各入口 obfuscation-rules.txt / 指南 §8.3）
# 产物与 debug 同名 -signed.hap（互相覆盖）；release 尺寸 entry 418.8 KB（−49.8%）
# nameCache/sourceMaps 在 outputs/default/symbol/release/ —— 必须随版本归档（崩溃栈反解）
devecocli build --build-mode release --modules entry entry_pc entry_tv entry_wearable
```

## 4. 启动装配（commons/AppCommon）

入口 Ability 不再手写初始化链，统一调 `AppBootstrap` 四静态方法（生命周期严格配对）：

```ts
// onCreate                → AppBootstrap.prepare(context)      // 兜底→主题→环境→存储→网络
// loadContent 回调         → AppBootstrap.attachWindow(ui, win) // 断点→安全区→方向→屏幕
// onWindowStageDestroy    → AppBootstrap.detachWindow()        // 与 attachWindow 成对
// onDestroy               → AppBootstrap.destroy()             // 与 prepare 成对
```

Toast 是表现层装配，不在 AppCommon（它不依赖 VitalUI/AppComponent，保手表可用）：entry / entry_tv 在 `loadContent` 回调里自行 `CommonToast.attach(...)` 闭包注入（CommonToast 现位于 @easystart/app-component，v3.22）。

## 6. 主题双机制

1. **深浅色（自动）**：页面只用 `$r('app.color.app_*')` 通用令牌 + `qj_brand` 族主题三件套（§9.4 契约），AppScope base/dark 两份 color.json 驱动，跟随系统。
2. **强调色（用户自由取色）**：`UiThemeManager`（@ObservedV2 单例）接受任意 `'#RRGGBB'`；`CommonColorPickerSheet`（bindSheet 半模态）选色，经 `PreferencesStore` 持久化（旧 `accent_preset` 键自动迁移）；组件通过 `accentColor` 参数消费。自由页面的开关/滑杆/进度/勾选/单选/分段要用 AppComponent `control/` 主题化工厂（选中态随强调色变，v3.15），**勿裸用 ArkUI 原生控件**（其选中色不随运行时换肤变）；设置页 HdsListItemCard 的 SuffixSwitch/SuffixSelect 保持 HDS 系统色、不绑 accent。**v3.21/v3.22 扩展**：Common* 基础封装（CommonDialog/CommonToast/CommonSearchBar）+ AppProgressDialog/AppOverlay/AppBadge + 换色 modifier 族（TextColor/Divider/Progress/Image）+ control/ 补全（Counter/LoadingProgress/Gauge/Select/Search/Refresh）。冷启动由 `AppBootstrap.restoreAccentColor()` 读出、phone/pc/tv 三端 Ability `onCreate` 注入 UiThemeManager（v3.15，手表不接）。

## 8. 扩展速查

> **本表是 趣开发 EasyStart 模板工程自身的扩展口径**。fork 应用对 `quizzyjoy/` 三库只读：表中动三库的行（加通用组件 / 加系统能力 / 改 Foundation 令牌）在应用工程内先走指南 §12.3 四档（域内 `util/` → `@<应用名>/common` → 提上游轮次），不得就地改；`commons/`（@<app>/*）与 features / 入口各行可在 fork 内直接操作。

| 我要… | 动这里 |
|---|---|
| 加业务特性 | 复制 `features/HomeFeature` → 根 build-profile 追加 → 入口 oh-package 加 `file:` 依赖；包名用 `@easystart/<域>` |

## 9. 硬性纪律（摘录）

- 状态管理只用 V2 装饰器（@ComponentV2/@ObservedV2/@Trace/@Local/@Param/@Monitor/@Computed）
- 断点只用 `UIContext.getWindowWidthBreakpoint()`，禁止硬编码像素阈值
- **kit 导入权限对所有层放开（v3.29 F14 修订，用户裁定）**：任何包可直接 import `@ohos`/`@kit`；跨应用通用且需复用/容错的能力**建议**收敛 Platform（ShareHelper 先例），单一使用方落域内 `util/`（判据 7，先例 DemoFeature util/ 三件）；Foundation 维持零 @ohos/@kit（LocalUnit 可测性）；系统类型（window/UIContext/common）可从 `@quizzyjoy/platform` 再导出获取
- 带参 @BuilderParam 必须具名参数 + 箭头包裹传 this；尾随闭包仅限无参单 BuilderParam
- 自定义组件带尾随闭包后不可链式调属性，样式放外层包容器
- throw 只接受 AppError；`@Entry` 结构体不 export
- 只从模块 `Index.ets` 导入，禁止深链 `src/main/ets/...`
