## 一、能力范围与效果

`ThemeControl.setDefaultTheme` 是官方提供的应用级主题入口（API 12 起）。使用前需明确它的边界：

| 项目 | 说明 |
|---|---|
| 生效范围 | 应用内所有 ArkUI 页面与系统组件的默认色，不涉及应用外（如桌面、通知栏） |
| 作用方式 | 覆盖 ArkUI 全局主题表中的语义令牌值 |
| 深浅色 | `CustomTheme.colors` 用于浅色，`darkColors`（API 20 起）用于深色，由系统按当前颜色模式自动选择 |
| 子树定制 | 需要局部不同主题时使用 `WithTheme` 组件（API 12 起），仅作用于其子树 |
| 读取时机 | 主题应用时可通过 `onWillApplyTheme(theme: Theme)` 回调读取最终值 |
| 不可用场景 | UIAbility / 窗口级、C API / Node-API |

效果如下。默认主题（品牌蓝）下的首页：

![默认主题下的首页：图标底与强调块为品牌色](图片/B2-home-brandblue.png)

切换主题后：

![切换后：品牌类颜色同步变化，危险色与成功色保持不变](图片/A8-components-teal2.png)

品牌装饰色跟随主题，语义色（危险 / 成功 / 警告）保持不变——后者是设计约定：语义不随主题改变。

## 二、四层颜色模型

屏幕上一处颜色的来源有四类，它们并列存在，不构成优先级关系。换肤如果"只变一半"，通常是只处理了其中一层。

| 层 | 机制 | 由谁决定颜色 | 未处理时的表现 | 工程落点 |
|---|---|---|---|---|
| L1 | 资源令牌 `$r('app.color.qj_*')` | 资源编译器（编译期固化） | 只随深浅色变 | `AppScope/resources/base/element/color.json` + `resources/dark/` |
| L2 | `AttributeModifier` 样式类 | 类中读取到的值 | 不参与运行时换色 | `commons/AppComponent/src/main/ets/modifier/` |
| L3 | 运行时主题单例 | 应用内单例的当前值 | 只有接入了单例的组件会变 | `quizzyjoy/VitalUI/src/main/ets/theme/UiThemeManager.ets` |
| L4 | `ThemeControl.setDefaultTheme` | ArkUI 全局主题表 | 系统控件保持系统默认色 | `quizzyjoy/Platform/src/main/ets/theme/AppThemeController.ets` |

四层的配合顺序是：L4 提供全局基线（系统组件与未显式着色的位置），L3 在其上做应用内的运行时覆盖（自绘组件），L2 处理无法参与观察的无状态样式，L1 承载"本来就该固定"的颜色（语义色、深浅色资源）。

## 四、四层的实现

### 4.1 L1 静态令牌

品牌令牌定义在 `AppScope/resources/base/element/color.json`：

```json
{ "name": "qj_brand", "value": "#0A59F7" },
{ "name": "qj_brand_light", "value": "#E8F0FE" },
{ "name": "qj_on_brand", "value": "#FFFFFF" }
```

深色值放在 `AppScope/resources/dark/element/color.json`，运行期由资源限定词自动切换。

页面中使用 `$r('app.color.qj_brand')`。该层不参与运行时换色，因此需要先对工程中的引用分类：

| 类别 | 处理方式 | 判定依据 |
|---|---|---|
| 品牌装饰色（图标底、强调块、选中态） | 改为读取 L3 的 `brandColor()` | 颜色本身应从属于主题 |
| 语义色（危险 / 成功 / 警告） | 保持令牌 | 语义固定，不应随主题改变 |
| 令牌对照页、设计规范演示页 | 保持令牌 | 页面职责是展示令牌原值 |

同一个色值可能同时出现在两类位置，需按语义逐个判断，不做全局替换。

### 4.2 L2 AttributeModifier

样式复用通过 `AttributeModifier` 实现，集中在 `commons/AppComponent/src/main/ets/modifier/`：`AppButtonModifier`（PRIMARY / SECONDARY / GHOST / DANGER）、`AppIconButtonModifier`、`AppProgressModifier`、`AppDividerModifier`、`AppInputModifier`。

```ts
export class AppButtonPrimaryModifier implements AttributeModifier<ButtonAttribute> {
  applyNormalAttribute(instance: ButtonAttribute): void {
    instance.backgroundColor(AppThemeApplier.brandColor());
  }
}
```

`AttributeModifier` 是普通类，不在组件的观察依赖图中，因此在其中读取单例的 `@Trace` 字段不会触发重渲染。工程采用静态中转：`AppThemeApplier` 在铺层时把当前色写入静态字段 `currentAccent`，并通过 `brandColor()` 暴露给 modifier。

约束：切换主题后，已渲染的 modifier 样式需等待页面重建才更新。需要即时响应的样式不应使用 modifier，应改为读取 `@Local theme` 的自绘组件。

### 4.3 L3 运行时主题单例

实现位于 `quizzyjoy/VitalUI/src/main/ets/theme/UiThemeManager.ets`：

```ts
@ObservedV2
export class UiThemeManager {
  private static instance: UiThemeManager | undefined = undefined;

  @Trace presetId: string = DEFAULT_THEME_PRESET;   // 当前主题包
  @Trace accentColor: string = '';                  // 强调色覆盖

  private constructor() {}

  static getInstance(): UiThemeManager {
    if (UiThemeManager.instance === undefined) {
      UiThemeManager.instance = new UiThemeManager();
    }
    return UiThemeManager.instance;
  }
}
```

组件接入方式：

```ts
@Local theme: UiThemeManager = UiThemeManager.getInstance();
```

`@Local` 建立依赖：组件订阅这两个字段，字段变化时读取过它们的位置当帧重渲染。

![切换主题后：取色块与预览组件同步变为新主题色](图片/A5-teal-applied.png)

#### 取色方法

| 方法 | 返回 | 说明 |
|---|---|---|
| `brandColor()` | `ResourceColor` | 品牌色。强调色优先；默认主题包回退 `$r('app.color.qj_brand')`，非默认包返回其基准色 |
| `effectiveAccent()` | `string`（hex） | 当前生效色字符串，供取色器、持久化与日志使用 |
| `onBrandColor()` | `ResourceColor` | 品牌底上的前景色，按感知亮度 `0.299R + 0.587G + 0.114B > 0.62` 选深色或白色 |
| `brandSoftColor()` | `ResourceColor` | 柔和层（chip 底、选中底）。默认包回退 `qj_brand_light`；自定义色返回 15% 透明度叠色 |
| `setAccentColor(hex)` | `void` | 空串表示清除强调色覆盖 |
| `setPresetId(id)` | `void` | 切换主题包 |
| `reset()` | `void` | 强调色与主题包同时回默认 |

#### 主题包

数据位于 `quizzyjoy/Foundation/src/main/ets/theme/AppThemePreset.ets`，每套只声明一个基准色：

```ts
new AppThemePreset('brand',    '品牌蓝', '#0A59F7'),   // 默认，与 qj_brand 同值
new AppThemePreset('teal',     '青碧',   '#12A594'),
new AppThemePreset('violet',   '靛紫',   '#6c4de8'),
new AppThemePreset('pink',     '桃粉',   '#D6409F'),
new AppThemePreset('contrast', '高对比', '#0A0A0A'),
```

其余令牌由 `AppThemeController` 派生，避免"5 套 × 7 个令牌 = 35 个手写值"的维护成本。

外观页中的呈现（选中态使用对应主题色描边）：

![五套主题包 chips，选中状态与当前生效色](图片/B1-presets-5.png)

#### 叠加关系

强调色与主题包是叠加关系：

```
最终色 = 强调色（有值则优先）→ 主题包基准色 → 静态令牌
```

```ts
brandColor(): ResourceColor {
  if (this.accentColor.length > 0) { return this.accentColor; }
  if (this.presetId === DEFAULT_THEME_PRESET) { return $r('app.color.qj_brand'); }
  return resolveThemePreset(this.presetId).baseHex;
}
```

默认主题包一支回退到令牌而非硬编码同值 hex，使深浅色仍由资源限定词负责，两套机制不冲突。

### 4.4 L4 系统组件默认色

实现位于 `quizzyjoy/Platform/src/main/ets/theme/AppThemeController.ets`，职责是把「一个品牌色 hex」翻译成 `CustomTheme`（含 `darkColors`），并调用 `ThemeControl`：

```ts
// AppThemeController.buildTheme(hex): CustomTheme
//   内部由 hex 派生七个令牌，并同时生成 darkColors
static buildTheme(hex: string): CustomTheme {
  return { colors: AppThemeController.lightColors(hex),      // private，7 个令牌
           darkColors: AppThemeController.darkColors(hex) };   // private，深色派生
}

// 对外入口：设置应用级默认主题
static applyPreset(presetId: string, accentHex: string): boolean { /* 幂等 + setDefaultTheme */ }
static clear(): void { ThemeControl.setDefaultTheme(undefined); }
```

#### 覆盖的令牌

工程覆盖以下七个令牌：

| 令牌 | 作用 | 工程取值方式 |
|---|---|---|
| `brand` | 全局品牌色（选中态、强调控件） | 主题包基准色 / 强调色 |
| `fontEmphasize` | 强调文字色 | 与品牌色同系 |
| `iconEmphasize` | 强调图标色 | 与品牌色同系 |
| `backgroundEmphasize` | 强调背景 | 品牌色的浅化层 |
| `compEmphasizeSecondary` | 次级强调（开关、滑块等控件的选中态） | 品牌色 |
| `compEmphasizeTertiary` | 三级强调（弱选中态） | 品牌色的弱化层 |
| `interactiveSelect` | 交互选中态 | 品牌色 |

#### colors 与 darkColors 成对提供

只提供 `colors` 时，深色模式会继续使用浅色值，出现亮底亮字的观感。两者也不能复用同一组值，深色需重新计算：

```
浅色：brand = 基准色；柔和层 = 基准色混 28% 黑
深色：brand = 基准色混 28% 白；柔和层 = 再混 82% 黑
```

#### 调用时机与容错

`setDefaultTheme` 需在 ArkUI 初始化完成后调用（`loadContent` 回调中），并且应包裹 `try/catch`：该调用失败不应阻塞启动，前三层仍可正常工作。实现中对相同颜色做了幂等短路，可安全重复调用。

生效后，系统弹窗中的主按钮也会跟随主题：

![统一对话框：确认按钮随主题变化](图片/A9-dialog-teal.png)

## 五、编排与启动接入

### 5.1 编排类

`commons/AppComponent/src/main/ets/theme/AppThemeApplier.ets`：

```ts
export class AppThemeApplier {
  private static currentAccent: string = '';

  static brandColor(): ResourceColor {                 // 供 L2 modifier 读取
    return AppThemeApplier.currentAccent.length > 0
      ? AppThemeApplier.currentAccent : $r('app.color.qj_brand');
  }

  static apply(presetId: string, accentHex: string): void {
    const theme: UiThemeManager = UiThemeManager.getInstance();
    theme.setPresetId(presetId);                              // 1. 先写 L3
    theme.setAccentColor(accentHex);
    AppThemeApplier.currentAccent = theme.effectiveAccent();  // 2. 更新静态中转
    AppThemeController.applyPreset(theme.presetId, theme.accentColor);  // 3. 再铺 L4
  }
}
```

顺序不可颠倒：先写单例，再算 `effectiveAccent()`，否则取到的是上一次的值，L4 会被铺成旧主题。

同类还提供两个局部入口：`applyPreset(presetId)` 仅切换主题包，`applyAccent(accentHex)` 仅设置强调色，二者内部都会重新走完整铺层，因此外观页可以在不重置另一维的前提下单独改一项。

### 5.2 冷启动恢复

`commons/AppCommon/src/main/ets/bootstrap/AppBootstrap.ets` 提供只读方法：

```ts
static async restoreTheme(): Promise<AppThemeState> { /* 读取偏好，返回 { presetId, accentHex } */ }
```

持久化键在 `commons/AppPreferences/src/main/ets/PreferenceKeys.ets`：`accent_color`、`theme_preset`。

### 5.3 各入口注入

在三个入口 Ability 的 `onCreate` 中调用（手表端不接入主题，故不调用）：

```ts
AppBootstrap.restoreTheme().then((state: AppThemeState): void => {
  AppThemeApplier.apply(state.presetId, state.accentHex);
});
```

| 入口 | 文件 |
|---|---|
| 手机 / 折叠 | `product/entry/src/main/ets/entryability/EntryAbility.ets` |
| 2in1 | `product/entry_pc/src/main/ets/pcability/PcAbility.ets` |
| TV | `product/entry_tv/src/main/ets/entryability/EntryTvAbility.ets` |

启动封装只负责读取、不依赖表现层 API，因此可被不需要 UI 主题的入口复用。

铺层完成后，整个窗口应呈现同一套配色（含宽屏分栏两侧）：

## 六、外观页交互

外观页实现位于 `commons/AppSettings/src/main/ets/component/AccentColorSetting.ets`，包含三部分：

1. **主题包 chips**：读取 `appThemePresets()` 渲染，选中态使用该主题包基准色描边；点击调用 `setPresetId` + `AppThemeApplier.applyPreset` + 持久化 `theme_preset`。
2. **取色器**：`CommonColorPickerSheet` 采用「拖动只写内部 draft，确认才回调」的契约，避免连续拖动产生大量重算与写入。
3. **效果预览**：主按钮 / 描边按钮 / 品牌标签三件，用当前生效色实时渲染。

```ts
private applyPreset(presetId: string): void {
  this.theme.setAccentColor('');            // 切包时清除强调色覆盖
  this.theme.setPresetId(presetId);
  AppThemeApplier.applyPreset(presetId);
  PreferencesStore.put(PreferenceKeys.THEME_PRESET, presetId);
  PreferencesStore.put(PreferenceKeys.ACCENT_COLOR, '');
}
```

切换主题包时清除强调色覆盖，是为了让用户看到主题包本身的效果；否则旧强调色（优先级更高）会盖住新主题包。

## 七、扩展方式

### 7.1 新增一套主题包

1. 在 `quizzyjoy/Foundation/src/main/ets/theme/AppThemePreset.ets` 的 `appThemePresets()` 中追加一行 `new AppThemePreset(id, label, baseHex)`；
2. 外观页会自动渲染新 chip，无需改动 UI；
3. 其余令牌由 `AppThemeController` 派生，无需新增配置。

### 7.2 新增要覆盖的系统令牌

在 `AppThemeController` 的 `lightColors(hex)` 与 `darkColors(hex)` 中同时增加对应字段（两处成对，深色版按同一规则重新计算），并确认 `applyPreset` 的幂等比较也包含该字段。

### 7.3 页面接入

| 场景 | 做法 |
|---|---|
| 页面装饰色 | 读 `this.theme.brandColor()`，需在组件内声明 `@Local theme: UiThemeManager = UiThemeManager.getInstance();` |
| 品牌底上的文字 / 图标 | 读 `this.theme.onBrandColor()` |
| chip 底、选中底 | 读 `this.theme.brandSoftColor()` |
| 语义色 | 继续使用令牌，不接入主题 |

### 7.4 组件接入

组件内部持有单例，同时开放外部覆盖入口：

```ts
@Local theme: UiThemeManager = UiThemeManager.getInstance();
@Param accentColor: string = '';

private accent(): ResourceColor {
  return this.accentColor.length > 0 ? this.accentColor : this.theme.brandColor();
}
```

两者都保留：仅靠传参容易漏传，仅靠单例则失去局部特调能力。

## 八、官方 API 速览

| API | 版本 | 用途 |
|---|---|---|
| `ThemeControl.setDefaultTheme(theme)` | API 12 | 设置应用级默认主题；传 `undefined` 清除 |
| `CustomTheme { colors?, darkColors? }` | API 12 / `darkColors` API 20 | 主题值容器，深浅色分别声明 |
| `WithTheme({ theme, colorMode })` | API 12 | 子树级主题覆盖；`BuilderNode` 场景需手动注入环境 |
| `onWillApplyTheme(theme: Theme)` | API 12 | 主题应用时的回调，可读取最终值 |
| `@ObservedV2` / `@Trace` | API 12 | 类属性级观测，用于运行时主题单例 |
| `UIContext.getHostContext()` / `promptAction` | — | 与主题无关，仅作入口侧能力说明 |

注意 `WithTheme` 只作用于其子树，若组件通过 `BuilderNode` 独立构建，需要手动注入主题环境。

## 九、易错点与正确写法

### 1. 强调色覆盖导致切换主题包无效

```ts
// 错误：只接受 7 位十六进制，空串被忽略
if (lower.length === 7 && lower.startsWith('#')) { this.accentColor = lower; }
```

现象：切换主题包后选中态变化，页面颜色不变。

![该界面处于强调色覆盖主题包的状态：色块显示的是强调色，而非主题包基准色](图片/A1-appearance.png)

原因：切包时需清除强调色覆盖（传空串），空串被忽略后旧强调色仍然生效。

```ts
// 正确：空串表示清除覆盖
setAccentColor(color: string): void {
  const lower: string = color.trim().toLowerCase();
  if (lower.length === 0) { this.accentColor = ''; return; }
  if (lower.length === 7 && lower.startsWith('#')) { this.accentColor = lower; }
}
```

切包时应同时清理内存与持久化值，否则重启后旧强调色会重新生效。

### 2. 组件未接入单例

```ts
// 错误
.backgroundColor($r('app.color.qj_brand'))
```

现象：页面装饰色随主题变化，该组件保持默认品牌色。原因是组件不认识运行时主题，只能依赖调用方传参。

```ts
// 正确
@Local theme: UiThemeManager = UiThemeManager.getInstance();
private accent(): ResourceColor {
  return this.accentColor.length > 0 ? this.accentColor : this.theme.brandColor();
}
```

### 3. 读取时机不在渲染路径上

```ts
// 错误 A：默认值只求值一次
@Param accentColor: string = UiThemeManager.getInstance().effectiveAccent();

// 错误 B：顶层 @Builder 无组件上下文，也无 this
@Builder
function floatingBall(content: BallContent) {
  .backgroundColor(UiThemeManager.getInstance().brandColor())
}
```

正确做法是改为 `@Local`，或在调用侧读取后通过数据对象传入：

```ts
class BallContent {
  tint: ResourceColor = $r('app.color.qj_brand');
}

const theme: UiThemeManager = UiThemeManager.getInstance();
content.tint = theme.brandColor();
```

### 4. 缺少 `darkColors`

现象：浅色正常，深色模式下底色与文字都偏亮。原因是系统在深色模式取不到对应值，继续使用浅色配置。

正确写法是成对提供，并按 4.4 的规则重新计算深色值。任何配色配置都应确认深色模式下的取值。
