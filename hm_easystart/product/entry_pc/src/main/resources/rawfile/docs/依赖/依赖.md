## 一、本工程的依赖形态

根 `hm_easystart/oh-package.json5` 使用了**参数化版本**：

```json5
{
  "parameterFile": "VersionFile.json5",
  "devDependencies": {
    "@ohos/hypium": "@param:dependencies.hypium-version"
  }
}
```

这带来一个直接后果：

```bash
ohpm install @luvi/lv-markdown-in
# ohpm ERROR: 00622008 Forbidden Install Error
# The "ohpm install <pkg>" command cannot be executed when the
# "parameterFile" configuration exists in the project-level oh-package.json5 file.
```

**所以在本工程里，`ohpm install <包名>` 一律不可用。** 正确姿势是三步：

1. 在需要它的**模块** `oh-package.json5` 里声明参数化版本：

```json5
{
  "dependencies": {
    "@luvi/lv-markdown-in": "@param:dependencies.lv-markdown-in-version"
  }
}
```

2. 在根 `VersionFile.json5` 里给参数赋真实版本：

```json5
{
  "dependencies": {
    "lv-markdown-in-version": "3.4.7"
  }
}
```

3. 在 `hm_easystart/` 根目录执行**不带包名**的安装：

```bash
cd hm_easystart
ohpm install
```

好处是版本集中在一个文件里，升级只改一处；代价是不能一条命令加包，必须手改两处。

## 二、选型审查清单

装之前逐条过一遍，任何一条不过就换库或自研。

| 检查项 | 怎么查 | 本例结果 |
|---|---|---|
| 许可 | `ohpm info <pkg>` 看 license | MIT，可商用 |
| 维护活跃度 | 版本数、最近发布时间 | 61 个版本，最近约 1 个月前 |
| 包体积 | 元数据 `size`，或装完量目录 | HAR 1.4MB，安装后 4.08MB |
| 是否 byteCode / 混淆 | 元数据 `metadata.byteCodeHar`、`obfuscated` | **是**，源码不可审 |
| 是否含原生 `.so` | 翻 `libs/` 目录 | **是**，传递依赖带仓颉运行时 |
| 兼容版本 | `compatibleSdkVersion` | 12 |
| 端支持 | 四端都构建一次 | 本例四端编译通过，运行时逐端验证 |

**传递依赖必须一起看。** `ohpm info` 只列直接依赖，要把每个包再查一遍：

```bash
ohpm info @luvi/lv-markdown-in          # deps: 3
ohpm info @cangjie-tpc/formula_hybrid   # 8.2MB，含 .so
ohpm info @cangjie-tpc/prism_hybrid     # 4.8MB，含 .so
```

本例实际代价：**安装总增量约 17MB**，其中两个仓颉 interop 包占了 13MB。

## 三、接入步骤

### 1. 声明并安装

按第一节的三步，模块选 `features/DemoFeature`（三方 UI 库只允许进 features / commons，见第六节）。

### 2. 引入并使用

```ts
import { Markdown, MarkdownController } from '@luvi/lv-markdown-in';

Markdown({
  controller: this.controller,
  mode: 'rawfile',                                  // 三种：text / rawfile / sandbox
  rawfilePath: 'docs/主题/主题.md',
  context: this.getUIContext().getHostContext() as common.UIAbilityContext
})
```

`mode: 'rawfile'` 是本例选它的关键：文档直接读 `resources/rawfile/docs/` 下的 md，不需要把内容塞进代码。

## 四、主题隔离（必做）

三方库自带一套默认配色。不做隔离，切主题时正文不会跟着变，视觉上就「一半新一半旧」。

做法：把库的样式 API 全部映射到本工程的 `UiThemeManager`：

```ts
export class DocTheme {
  static style(theme: UiThemeManager): MarkdownController {
    const controller: MarkdownController = new MarkdownController();
    controller
      .setTitleColor($r('app.color.app_text_primary'))
      .setTextColor($r('app.color.app_text_primary'))
      .setInlineCodeColor(theme.brandColor())          // 行内码前景 = 品牌色
      .setInlineCodeBackgroundColor(theme.brandSoftColor())
      .setQuoteBorderColor(theme.brandColor())
      .setCodeBlockBorderRadius(AppRadius.MD)
      .setTableInnerBorderColor($r('app.color.app_divider'));
    return controller;
  }
}
```

原则：**库的颜色只能来自我们的主题**，不允许出现库的默认色。

> 补充：HDS 组件（页签、列表卡）不吃 `ThemeControl`，需要显式传色，且**必须传 hex 字符串**——传 `$r(...)` 在 build 之外构造时会回落默认色。详见 `教程/主题/主题.md` 的第 4.5 节。

## 五、资源路径：图片要换写法

库识别的是 rawfile 形式，不是相对路径：

```markdown
![]($rawfile("docs/依赖/$rawfile("docs/主题/图片/B2-home-brandblue.png"")))
```

而仓库里的文档要保持 `图片/x.png`（这样 GitHub、编辑器都能直接预览）。所以在同步脚本 `scripts/sync-docs.mjs` 里做一次转换：源码 md 原样保留，**只有拷进 rawfile 的副本**被改写成 `$rawfile(...)`。

## 六、分层约束

| 层 | 能否引入三方库 |
|---|---|
| `quizzyjoy/*`（Foundation / Platform / VitalUI） | **禁止**。三库是零依赖底座，要能被换一个 app 直接复用 |
| `commons/*` | 可以，需评估体积与许可 |
| `features/*` | 可以，演示性 / 业务性依赖优先放这里 |
| `product/*` | 尽量不直接引入，避免各端版本漂移 |

## 七、版本治理

1. **版本只写在 `VersionFile.json5`**，模块里引用 `@param:` 参数，杜绝两处版本不一致；
2. `oh-package-lock.json5` 入库，保证 CI 与本地装到同一版本；
3. 升级时看 changelog，重点看：破坏性改动、新增原生依赖、`compatibleSdkVersion` 变化；
4. 升级后必须重跑四端构建 + 受影响页面截图对照。

## 八、卸载与回退

三方接入失败或体积不可接受时，按顺序回退：

1. 删模块 `oh-package.json5` 里的依赖行；
2. 删 `VersionFile.json5` 里的版本参数；
3. 根目录 `ohpm install`（会清掉不再被引用的包）；
4. 删除引用该库的代码与样式映射；
5. 重跑四端构建确认没有残留引用。

因为依赖只在**一处**声明，回退是单点操作，不需要到处找。

## 十、常见问题

**Q：`ohpm install <pkg>` 报 00622008？**
本工程用 `parameterFile` 参数化依赖，只能手改模块声明 + 版本文件，再在根目录 `ohpm install`。

**Q：装完编译报 `Cannot find module`？**
依赖要声明在**真正 import 它的那个模块**的 `oh-package.json5` 里，不是根 `oh-package.json5`。

**Q：包里有 `.so`，会不会影响 TV / 手表？**
编译期会检查 ABI，但运行期仍可能因系统组件缺失而失败。含原生库的依赖必须在每个目标端真跑一次，不能只看构建结果。

**Q：byteCode / obfuscated 的包怎么审？**
看不到源码，只能审行为：体积、依赖、权限（`module.json5` 是否要求额外权限）、网络请求，以及在小范围页面上先试。对安全敏感的工程，这类包应慎用或自研替代。

**Q：三方组件不跟随主题怎么办？**
找它的样式 API，全部映射到 `UiThemeManager`；没有样式 API 的库，用外层容器控制背景与文字，或直接放弃该库。
