# 第 13 章 验收清单、回归矩阵与 fork 接入顺序

> 本章成稿目标字数：2000–2600 ｜ 预计阅读 9 分钟 ｜ 前置：全书

## 本章要解决的问题

**怎么证明「换肤真的完整了」，而不是「我看的那几页对了」？**

本章把前 12 章的结论收敛成三样东西：一张可勾选的验收清单、一张四端回归矩阵、一份 fork 接入顺序。它们的作用是**把主观观感变成可复现的判定**。

## 读者收获

1. 一份可以直接贴进 PR 描述的验收清单；
2. 四端各自的「必测页面 + 已知差异」；
3. 一条「先做什么、后做什么」的接入顺序（顺序错了会重复踩坑）。

---

## 13.1 验收清单（逐条可勾）

### A. 四层是否都接上

- [ ] 改强调色 → 自绘组件（按钮/标签/chip/加载）**立即**变（L3）
- [ ] 切主题包（不设强调色）→ 自绘组件变（验 `brandColor()` 回退链，第 5 章 §5.4）
- [ ] 对话框主按钮 / 填充按钮 / 开关选中（原生）变（L4）
- [ ] `AttributeModifier` 渲染的组件在**页面重建后**变（L2，接受延迟，第 4 章）
- [ ] 令牌对照页 / 语义色（危险/成功/警告）**不变**（B/C 类，第 3 章）
- [ ] HDS 组件：提供显式传色口子的变了（开关），未提供的**明确记为已知不跟随**（第 11 章）

### B. 优先级与清除语义

- [ ] 设了强调色后切主题包 → 强调色被清，颜色跟随新主题包（坑 1，第 8 章）
- [ ] 点「恢复默认强调色」→ 回到**当前主题包**基准色，而不是回默认主题包（第 8 章）
- [ ] 杀进程重进 → 主题包 + 强调色都正确恢复（持久化与内存一致）
- [ ] 手动写入非法 hex 后启动 → 不崩、回退主题包、日志有 warn（第 7 章 §7.4）

### C. 深浅色

- [ ] 浅 → 深 → 浅 往返切换，品牌色不发白/不刺眼（`darkColors` 生效，第 6 章）
- [ ] 深色下自绘品牌色与系统品牌色**明度差可接受**（第 3 章 §3.6 已知偏差）
- [ ] 深色下对话框、开关、SnackBar 全部可读

### D. 冷启动与性能

- [ ] 冷启动**无可见闪色**（若闪，按第 7 章 §7.7 三方案缓解）
- [ ] 切主题后无持续掉帧；长列表滚动正常（`@Trace` 重渲染范围可控）
- [ ] `hilog` 中无 `GetColorById error` 类取色失败

### E. 布局与容器宽（与主题同等重要）

- [ ] 分栏下左栏宽度落在 340–420vp 区间（第 12 章）
- [ ] 分栏下所有网格按**容器宽**分档，无「卡片被压到标题只剩一个字」
- [ ] 分栏下页签在**左栏底部**，不在顶部
- [ ] 页签覆盖内容时，列表末尾一行完整可见（底部 padding 已预留）

## 13.2 四端回归矩阵

| 端 | 入口 | 必测页面 | 已知差异 / 注意 |
|---|---|---|---|
| **手机/折叠**（`entry`） | `EntryAbility` | 首页、示例 L1/L2/L3、外观页、通用设置、对话框、宽屏分栏态 | 折叠展开进分栏（左栏宽度与列数、页签位置） |
| **2in1**（`entry_pc`） | `PcAbility` | 分栏首页、工具网格、外观页 | 页签天生在底部；分栏是常态，容器宽稳定 |
| **TV**（`entry_tv`） | `EntryTvAbility` | 首屏、列表焦点态 | **焦点态颜色**另有一套（需单独确认是否跟主题）→ 需复核 |
| **手表**（`entry_wearable`） | 不调用 `restoreTheme` | 首屏 | **明确不支持主题**（产品决策，不是缺陷） |

回归执行建议：

1. 每端至少 1 台真机 + 1 个模拟器（模拟器用于快速回归，真机用于取像素）；
2. 每轮改色后**逐页截图**，而不是「扫一眼」——「看起来对」是漏检的主要来源；
3. 分栏态必须单独截：**同一页在 `Stack` 与 `Split` 下是两种布局**。

## 13.3 fork 接入顺序（顺序错了会重复踩坑）

推荐的实施顺序及理由：

| 步骤 | 做什么 | 为什么必须在这个位置 |
|---|---|---|
| **1** | 建 L3 单例（`UiThemeManager`）+ 你的原语接入 `@Local theme` | 所有自绘组件的基础；先有它才能验证「谁没接」 |
| **2** | 建 L4（`CustomTheme` + `darkColors` 成对）+ 落地器 | 补系统组件断层；越晚做，走查时「系统蓝」的噪声越多 |
| **3** | 接冷启动恢复（`restoreTheme` + 各入口 `apply`） | 否则每次重启都要手动设，走查效率极低 |
| **4** | 全仓取证 + 分级（A/B/C 三类） | 有前三步才有「变/不变」的对照基线；分级避免误改演示页与语义色 |
| **5** | L2 modifier 接静态中转 | 改动面小、风险低，放中段 |
| **6** | HDS 逐组件找显式传色口子 | 需要逐个查 `d.ts`，最耗时，放后面 |
| **7** | 布局与容器宽修复（分栏/页签） | **放最后**：它会改变观感，提前做会污染主题走查的对照 |
| **8** | 验收清单逐条过 + 四端矩阵 | 收口 |

两条反直觉但重要的顺序约束：

- **第 4 步（取证分级）不能放到第 1 步之前**——没有 L3/L4，「变/不变」的对照无法建立，取证只能得到一堆静态色值；
- **第 7 步（布局）不能放到前面**——分栏会把「主题问题」与「截断问题」混在一起（第 12 章开头已述）。

## 13.4 已知遗留与决策记录（写进 README，别写进「待办」）

把「决策」与「缺陷」分开记，是这套系统能长期维护的关键：

| 项 | 类型 | 说明 |
|---|---|---|
| 卡片（ArkTS）不跟随主题 | **决策** | V1 框架限制，保留 `$r` 是正解（第 10 章） |
| 手表不支持主题 | **决策** | 小屏收益低、风险高（第 7 章） |
| 非默认主题包暗色下自绘色不提亮 | **已知偏差** | 取舍换来的（第 3 章 §3.6） |
| modifier 需页面重建才刷新 | **已知限制** | 源码注释已声明（第 4 章） |
| HDS 卡片底色/分割线/chevron 不跟随 | **遗留** | 需 `HdsListItemCardModifier`，未做（第 11 章） |
| 设置域 builtin 行未全部接显式传色 | **遗留** | 影响「100% 跟随」判定（第 11 章） |
| 搜索行「取消」仍系统蓝 | **遗留** | 不在注入面，实现路径待复核（第 8 章） |

> 纪律：**「遗留」可以排期，「决策」不要排期**。把决策挂进待办清单，会让后来者反复尝试一件已经论证过不该做的事。

---

## 13.5 一句话总结全书

> 换肤不是「换一个颜色」，而是**四层各管一段、按顺序编排、逐体系取证**：
> L4 兜住系统组件，L3 管住自绘组件的即时性，L2 保留特调，L1 守住语义与深浅色；
> 优先级与清除语义要显式表达；HDS 与 V1 卡片的边界要承认；
> 最后用容器宽而不是窗口断点来画界面。
